# SEO runbook

What this repo does about search, how to keep it working, and the three things
that still need a human with the right logins.

Generated while working through `ACTION-PLAN.md` from the 2026-07-25 audit
(score 71/100 at the time).

---

## The one change that mattered

Before this, the site had 106 markdown files of curriculum and exactly **one**
indexable page, and its homepage carried 77 anchors of which **zero** were
internal and 70 pointed at github.com.

Now 150 curriculum pages are published on this domain and the homepage is 73
internal / 5 outbound. Nothing new was written — the content already existed, it
was just living on someone else's domain.

```
content/          vendored from the course repo by scripts/sync-docs.mjs
lib/docs.ts       the URL map: content path -> route
lib/markdown.ts   markdown -> HTML, with link rewriting + pre-rendered diagrams
app/[...slug]/    one route, 150 prerendered pages
```

## Commands

| Command | What it does |
|---|---|
| `npm run sync:docs` | Re-vendor the curriculum after the course repo changes. Renders any new mermaid diagrams to SVG (needs Chrome; uses `npx @mermaid-js/mermaid-cli`, not a dependency). |
| `npm run build` | Generates `og.png` + `llms.txt`, then the static export. |
| `npm run check:links` | Verifies every internal link in `out/` resolves. **Run after every build.** |
| `npm run indexnow` | Pushes the sitemap's URLs to Bing/IndexNow. Run *after* a deploy, never before. |
| `npm run og` | Regenerate the social cards on their own. |

### Syncing the curriculum

```bash
npm run sync:docs                     # reads ../loop-project-seo
COURSE_REPO=/path/to/course npm run sync:docs
npm run sync:docs -- --skip-diagrams  # markdown only, reuse cached SVGs
```

`content/SOURCE.json` records which commit of the course repo the current content
came from.

If you rename a folder in the course repo, update the `DIR_URL` map in
`lib/docs.ts` in the same change — otherwise the routes move and every existing
link to them 404s. `npm run check:links` is what catches this.

### What is deliberately not published

The 21 starter kits each ship six scaffold files (`LOOP.md`, `loop-budget.md`,
`loop-constraints.md`, `loop-run-log.md`, `<name>-state.md`). Those are config
templates, not prose; publishing 126 near-identical files would be index bloat.
Each kit's `README.md` **is** published. The filter lives in `scripts/sync-docs.mjs`.

## Still needs you — three items no script can do

### 1. Google Search Console (audit item C3) — **highest priority**

Neither property is indexed. An exact-match search for `"LoopEngineering-CrashCourse"`
currently returns nothing. This is the single blocking item: everything above is
invisible until Google has the sitemap.

The verification file is already in place and already deployed
(`public/google1e6823c3613c1e2e.html`), so verification should succeed immediately.

1. <https://search.google.com/search-console> → add property →
   **URL prefix** → `https://ayeshakhalid192007-dev.github.io/loop-lab/`
2. Verify via **HTML file** — it is already being served.
3. **Sitemaps** → submit `sitemap.xml`.
   You cannot declare it in `robots.txt`: on `*.github.io`, robots.txt is only
   honoured at the domain root, which a project site does not control. Search
   Console submission is the only discovery path Google has.
4. **URL Inspection** → request indexing for the homepage and for
   `/foundations/glossary/` (the highest-value single page — definitional queries
   like *what is a heartbeat in an agent loop* are the winnable ones).

Then the same in [Bing Webmaster Tools](https://www.bing.com/webmasters) —
`public/BingSiteAuth.xml` and the `msvalidate.01` meta tag are both already live,
so either method verifies. Bing also unlocks a free API key for the backlink
tooling, which is currently at Tier 0.

**After the deploy lands**, run `npm run indexnow` to push all 156 URLs to Bing
directly. Not before — submitting URLs that 404 is worse than not submitting.

### 2. Repo social preview (M5)

`assets/social-preview.png` (1280×640) is generated by `npm run og`. GitHub has no
API for this, so it has to be uploaded by hand:

**Repo → Settings → Social preview → Edit → Upload an image.**

Do it on the course repo (`LoopEngineering-CrashCourse`), which is the one people
share. Until then every share of that link carries GitHub's auto-generated card.

### 3. Google API key (M6)

`google_auth.py --check` reports Tier -1 — all six APIs unavailable. A free key
unlocks PageSpeed Insights and CrUX, which turns the performance numbers from a
single lab sample into real field data. That matters specifically because the
CLS 0.334 finding needs field confirmation.

```
GOOGLE_API_KEY=…      # or add "api_key" to ~/.config/claude-seo/google-api.json
```

## Assessed and deliberately not done

**L3 — inline RSC payload.** Measured after the changes: 42 `self.__next_f.push`
blocks, 111,183 chars inline on the homepage (48,214 on a curriculum page). It
gzips to ~28 KB, so the network cost is genuinely modest, and it is inherent to
the App Router's static export — there is no supported way to trim it that does
not mean deleting client components the page actually uses. The audit rates this
LOW and says the same. Left alone on purpose; re-evaluate only if a field CWV
measurement shows parse time is actually hurting.

**L1 — claiming the domain root.** `https://ayeshakhalid192007-dev.github.io/`
404s. Creating a `<username>.github.io` repo would allow a root `robots.txt` with
a `Sitemap:` line. Worth weighing against just buying a real domain, which would
be better for brand, backlinks and portability. Not a code change either way.

**L4 — `offers` on Course.** `isAccessibleForFree: true` already communicates
this and is what Google reads. An explicit `Offer` with `price: "0"` is redundant
for Google and only helps some aggregators. Skipped.

## Invariants — things that will break search if changed carelessly

- **Trailing slashes.** `next.config.ts` sets `trailingSlash: true`. Canonicals,
  `sitemap.ts` and the route URLs in `lib/docs.ts` must all agree. A mismatch
  tells Google two different things about one page.
- **`basePath` on raw HTML.** Next applies `basePath` to `<Link>`/`<Image>` but
  **not** to raw HTML. Curriculum pages are rendered markdown, so every link and
  image in them goes through `withBasePath()` in `lib/base-path.ts`. Without it
  they work in dev and 404 in production.
- **No `app/robots.ts`.** Intentional — see the Search Console note above.
- **No `app/opengraph-image.tsx`.** Also intentional: it emitted an extensionless
  route, and GitHub Pages types responses purely from the file extension, so it
  was served as `application/octet-stream` while the markup claimed `image/png`.
  The card is a real `public/og.png` now.
- **FAQ markup belongs on the homepage only.** Google requires FAQ content to be
  visible on the page carrying the markup. `components/JsonLd.tsx` is rendered by
  `app/page.tsx`, not by the root layout — do not move it back.

## Do not

Straight from the action plan, still true:

- **Do not optimise the GitHub repo page further.** Description, homepage and
  topics are set; that is every lever GitHub gives you. Title, canonical and
  schema are GitHub's and stay GitHub's.
- **Do not remove the `agentfactory.panaversity.org` links** from the README.
  They are honest attribution in a credits section, even though that site
  currently ranks for the exact course title.
- **Do not treat `llms.txt` as a ranking lever.** It is a convention, not a
  standard, and Google has said it does not use it. It is generated from the real
  route table now so it cannot drift; that is all it needs to be.
- **Do not chase "loop engineering" as a head term yet.** Against an exact-match
  domain, a Udemy course and Addy Osmani's originating post, the winnable queries
  are definitional long-tail — which the glossary and the FAQ schema already answer.
